# Architecture evidence for arbitrary TP/SL first-touch probabilities

Research date: 2026-10-23. Read-only investigation of numerical code and frozen results. No model, data, run, training or GPU changes. External facts below come from ten primary studies and their official implementations. Proposed adaptations are hypotheses, not published financial results.

## Decision

Keep the compact multiscale history encoder and competing-risk likelihood. First test a level-aware decoder and a short, uncompressed M1 branch. Then test synchronized cross-asset context and history-only self-supervision. A large forecast foundation model with native adaptation is a useful controlled competitor, but its forecast head does not solve arbitrary first passage. A wholesale architecture replacement has weaker justification than these isolated changes.

## What the present evidence actually says

The local [model](../../../../../wallex_lab/barrier_survival.py) encodes three overlapping scales once per origin and cross-attends with barrier and time-bin queries. For the selected week context, the token counts are 720/6 = 120, 2880/15/3 = 64, and 10080/60 = 168, totaling 352. With 128 requests and five bins, the decoder has 640 queries. These are calculations from `MultiScaleSurvival.layout` and `forward`, not measured profiling results. The supplied configuration is width 96, three layers, approximately 382 thousand parameters.

The [frozen report](../../experiments/barrier-survival-multiday-20261022/report.md) shows that history helps most at intermediate horizons. Late-fold calibrated log loss at 60 minutes is 0.64206 versus 0.67133 for query-only. At 1440 minutes it is 0.70468 versus 0.70539, a much smaller difference. The week context won early validation, but context length and aggregation layout changed together. This does not isolate a benefit from additional historical minutes. Repeated nearby origins and barrier requests are correlated; they do not provide 128 independent training examples per origin.

The current model already preserves OHLC extrema when making coarse bars, uses convolutional patches, conditions on requested levels, and constructs coherent cumulative incidence across time. Its immediate gaps are more specific: coarse OHLC loses within-bar chronology; M1 patches compress six minutes into one vector; position indexes do not explicitly express physical elapsed time across overlapping scales; and an asset identity embedding supplies no contemporaneous information about other assets. None of these observations proves a predictive defect. They define testable changes.

## Most promising target, built incrementally

The proposed target is the existing 352-token encoder with a small M1 convolutional residual, explicit age/duration features, and continuous level-conditioned attention. Cross-asset summaries remain an optional residual input. Keep the current five-bin event head, censoring rules, price/volume invariance, query coverage and FP32 likelihood. Width 96 is the starting point; a larger width is a separate capacity control.

All changes in this section are our hypotheses.

1. Add token age in minutes and token duration alongside the existing scale and learned position embeddings. A token from 30 minutes ago should expose that age directly even when it belongs to a different scale. Compare against the existing encoder with everything else fixed.
2. Give the decoder explicit signed distances from each requested barrier to historical token high, low and close, in the same causal volatility-normalized log-price coordinates used by the current input. A tiny shared function can turn those distances, age and duration into an additive attention bias. Keep continuous distances rather than binning levels into a fixed grid. This lets different barriers retrieve different parts of the same encoded history without re-encoding it 128 times. For short positions, the price-axis ordering of upper/lower levels must remain separate from the TP/SL cause labels.
3. Preserve the last 30 to 60 completed M1 bars in a small residual convolution branch. Pool its output into a few local tokens or a decoder residual. This tests whether six-minute patch compression hides short-horizon approach speed, wick structure or repeated approaches. Start with one branch and one receptive-field choice, not a catalogue of pattern detectors. The existing patch projection is linear over six candles, so it can retain some ordering information; it should not be described as an orderless six-minute OHLC bar.
4. Add only synchronized BTC/ETH or a fixed market-basket summary first. Use past returns, range/volatility and volume, plus observation/missingness information. A shared small context encoder and a gate are enough to test usefulness. Timestamp joins must use completed bars available at the query origin, never the nearest future timestamp. A symbol embedding does not substitute for these inputs. If BTC/ETH are unavailable in the approved data, this is a data expansion proposal, not an architecture-only test.

Explicit level distances make relevant geometry easier to learn. They do not enforce cross-barrier monotonicity or reconstruct the chronology lost in historical aggregated OHLC. Keep those guarantees separate from the architecture claim.

## Pretraining and foundation-model adaptation

First test masked reconstruction on our own compact encoder, initialized from scratch. Mask contiguous historical intervals and hide their representations at every overlapping scale. Otherwise the M15/M60 branch may reveal the masked M1 prices almost directly. Reconstruct normalized returns, candle ranges and volume with a small disposable head. Use only the training period of each fold for normalization fitting and pretraining; unlabeled validation/test histories still contaminate a strict prospective transfer experiment if used in pretraining. Bidirectional attention within a window ending at the completed origin is compatible with this task, because every input is historical at prediction time.

Next compare a TS2Vec-style contrastive objective against reconstruction at the same encoder size and total training budget. Overlapping views should refer to the same historical interval. Avoid time reversal, price-axis reversal without swapping event semantics, and arbitrary crop pairs that remove the approach to the queried region. These augmentations can erase exactly the directional morphology the downstream target needs. Compare supervised-only, pretraining then frozen head, and pretraining then end-to-end fine-tuning. Better reconstruction or retrieval is a diagnostic; downstream partial-label NLL and calibration determine success.

The official [Chronos-2 model card](https://huggingface.co/amazon/chronos-2) currently describes a 120-million-parameter encoder-only model, group attention, native multivariate inputs, real/categorical past covariates, and known-future covariates. It lists maximum context 8192 and prediction length 1024. Native M1 input therefore does not fit the present 10080-minute week without truncation, resampling or an explicit multiscale adapter. Its multi-step quantile forecasts are not joint OHLC trajectories or first-touch probabilities.

The current official [Chronos-2 pipeline source](https://github.com/amazon-science/chronos-forecasting/blob/main/src/chronos/chronos2/pipeline.py) implements `fit(..., finetune_mode="full" | "lora")`. Its default LoRA configuration has rank 8, alpha 16 and attention q/k/v/o plus the forecast output layer as targets. This API fine-tunes the forecasting objective; attaching our event decoder and training on our censored NLL requires a custom integration. In the inspected source, missing `peft` triggers a warning and falls back to full fine-tuning. Verify the actual trainable parameters and pin the implementation before any future run.

Use one checkpoint and one input adapter for this controlled comparison: frozen encoder plus event head; encoder LoRA plus the same event head trained directly on event NLL; and a budget-matched compact model. If practical, add native forecast adaptation followed by event adaptation to distinguish domain adaptation from task adaptation. Report base-checkpoint identity and pretraining-data overlap uncertainty. A frozen head result alone cannot settle whether native adaptation helps; LoRA adds task-adaptable representation capacity but retains base-model forward and activation costs.

Marginal future price quantiles cannot identify first passage. The event depends on the path and which barrier is reached first; even accurate terminal distributions leave that order undetermined. A simulation baseline would require an explicit joint path model, valid OHLC construction and a documented same-minute ambiguity policy. Do not turn independent per-horizon quantile draws into a claimed first-touch model.

## Compute tradeoffs and experiment order

These are analytical estimates and proposed controls, not GPU benchmarks.

| Change | Main cost and reason for priority |
|---|---|
| Age/duration features | Negligible input projection change; unchanged token count. Lowest-cost test. |
| Level-relative attention bias | Approximately O(KN) pair features for K=128 and N=352, shared across bins where possible. No extra history encoder runs. Measure whether attention fusion is lost with the bias implementation. |
| Short M1 convolution residual | Linear in the short history length; a handful of summary tokens avoids a large self-attention increase. Adding 60 tokens globally would change encoder pair count from 352² to 412², about 1.37 times, and decoder pair count by about 1.17 times. Actual runtime also includes projections, feed-forward blocks and kernels. |
| Cross-asset context | Separate small encoders and summaries avoid flattening every asset into one full attention sequence. An extra asset branch has acquisition, join and missingness costs as well as FLOPs. |
| Reconstruction pretraining | Adds training work once per fold, then reuses the encoder for all 128 requests. Include pretraining in the total budget; do not compare equal downstream epochs as equal cost. |
| TCN/TimeMixer replacement | Can reduce sequence-mixing cost, but fixed-length temporal MLPs and receptive-field choices need controls. Keep decoder and loss identical. |
| State-space replacement | Linear sequence mixing matters most if fine-resolution token length grows. It does not remove the O(KN) decoder unless that decoder is changed too. |
| Native foundation model with LoRA | 120M versus approximately 0.382M is about 314 times as many base parameters, not a 314-times runtime estimate. Bare 120M BF16 weights alone are about 240 MB, excluding gradients, adapters, optimizer states and activations. Frozen embeddings can be cached only when input transforms are fixed; LoRA generally invalidates that cache. |
| Sparse MoE | Adds router and expert-state overhead. Defer until dense capacity and useful regime/context dependence have been demonstrated. |

The baseline encoder attention has 352² = 123904 score pairs per head per layer. The decoder has 640×352 = 225280 per head. With three encoder layers, their total score-pair count is 371712 per head, so decoder attention is already a meaningful fraction. Replacing only the encoder with a linear-time backbone cannot eliminate all attention cost. These counts are useful for choosing ablations, not a substitute for profiling.

Run isolated tests in this order: age/duration; level-aware attention; local M1 residual; synchronized market context; masked pretraining; contrastive pretraining; alternative backbone; native foundation adaptation. Combine only changes that win independently, then test interactions. Include a plain width/depth increase as a parameter-budget control before crediting a sophisticated architecture.

Use common eligible origins, the same 128 requests, matched seeds, the existing purge rules, fixed event bins and identical censoring semantics. Select on validation partial-label NLL. Compare both fixed optimizer-update budgets and fixed total compute budgets. Score calibrated and raw event loss/Brier by horizon, asset, direction, distance and volatility regime, with day-block uncertainty. Retain query-only and current-history baselines. Separate historical exploratory results from an untouched future period. Inspect cross-barrier consistency, sensitivity to plausible historical perturbations and missing-context behavior. A favorable attention plot or a named pattern example is insufficient evidence of either predictive skill or semantic pattern recognition.
